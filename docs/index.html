The story

IEvery college tournament has the same ending: a notebook, a WhatsApp group and an argument about the points table.

IIA wrong entry can change a result. Nobody knows who typed it. Nobody can undo it.

IIISo we asked a different question: what if every ball was a record, every rule lived in the database, and every spectator saw the score the instant it happened?

IVThat is PitchSide. Three databases, each doing the one job it is best at.

Three databases, three jobs

MySQL

The rulebook

Teams, players, fixtures, users. Constraints, a view, a trigger that updates points, and a stored procedure that finishes a match inside a transaction.

MongoDB

The memory

Every ball is a document. Aggregation pipelines turn them into strike rates, charts, Player of the Match and an audit trail.

Redis

The loudspeaker

Live counters, a sorted-set leaderboard and pub/sub that pushes each ball to every open screen over a WebSocket.

One ball, five steps

3MongoDB saves the ball
